# Build, verify, deploy

## Build

- Default stack: Next.js (App Router) + Tailwind v4 + `motion` + `lucide-react`, deployed on Vercel. Scaffold with
  `npx create-next-app@latest . --ts --tailwind --eslint --app --src-dir --import-alias "@/*" --use-npm --disable-git
  --yes` (move any existing files out first; it refuses a non-empty folder).
- The installed Next is newer than training data: read `node_modules/next/dist/docs/` (fonts, images,
  view-transitions) before writing code. `AGENTS.md` in the scaffold says so too.
- Tokens: measured palette into `@theme` (`--color-*`), easing tokens, the font via `next/font/google`, `::selection`,
  focus rings and scrollbar themed from the palette.
- Content lives in `src/content/*.ts` (verbatim client copy, generated by script where possible); components in
  `src/components`; templates from `assets/templates/` (motion.css, film, page-shell, browser-window, words,
  count-up).
- A value exported from a `'use client'` module reaches a server component only as a client reference
  (`FACTS[key]` was undefined and the page 500'd). Shared data goes in a plain module.
- Hole-free grids: pick the column count from the item count, or span the first/last item (5 people: first spans
  two at tablet width).
- `next/image` caches optimized images by URL in `.next/cache/images`: after replacing a file under the same name the
  old version keeps serving. Never overwrite an image in place: give the new one a new name. (8x Playmakers: the step
  pictures were swapped under the same names and the user kept seeing the old lenses; your own fresh test browser
  hides this, because the cache is on the server.)
- Commit as the user, with the git identity in `local.md` (or the repo's own config): `git -c user.name=<name> -c
  user.email=<email> commit` with a `type(scope): lowercase subject` header (72 chars max), a blank line, a body, and the Co-Authored-By trailer
  the session asks for.

## Platform notes

The scripts behave the same on Windows, macOS and Linux; the shell around them differs.

- Python is `python3` on most macOS and Linux machines and may be `py` on Windows; use whichever exists.
- Windows (Git Bash): heredocs eat backslashes (`python - <<'EOF'` turns `\\` into `\`), so write scripts with the
  Write tool, then run them. Arguments that start with `/` get rewritten into Windows paths: prefix
  `MSYS_NO_PATHCONV=1`.
- `preview_start` (Claude desktop app) reads launch configs from the session's root project and refuses a `cwd`
  outside it. When the site lives elsewhere, link it into the session folder and use `"cwd": "<name>"`: on Windows a
  junction (`New-Item -ItemType Junction -Path "<session>\<name>" -Target "<site>"`), on macOS and Linux a symlink
  (`ln -s "<site>" "<session>/<name>"`). Or move the session with change_directory (takes effect next turn).
- Stopping a background `npm run dev` can orphan `next` and embedded `postgres`; see what holds a port with
  `Get-NetTCPConnection -LocalPort <port>` (Windows) or `lsof -i :<port>` (macOS, Linux).
- Where `preview_start` exists, run dev servers with it, never with Bash. Elsewhere start them in the background and
  stop them by PID.

## Verify (two rounds at most, then stop polishing)

1. `npx tsc --noEmit`, then `npx next build` (production build must pass).
2. `python scripts/check_site.py http://localhost:<port> --paths <every route> /nope --perf`: statuses, console
   errors, horizontal overflow, 60fps, full wheel-scroll distance from over the hero. Run it again with `--phone`.
   Measure overflow against the width you set, never `innerWidth`: mobile emulation zooms out to fit a too-wide page,
   so `innerWidth` grows with the overflow and hides it.
3. `python scripts/tour.py <url> <dir> --name home` and again with `--phone`: read the sheets for blank or
   half-revealed sections, empty bands inside mocks, text over busy images, cut-off endings.
4. Script the key interactions with Playwright (open/close the film; the slider advancing with the mouse resting on
   the hero; the pause button) and assert on DOM state.
5. Show the user real screenshots (SendUserFile, `display: render`): hero crops at full size plus a tour sheet.
   Keep the pane on the running site so they can poke it.

## Deploy (Vercel)

- Find the scope: the one the user names, else their usual one in `local.md`, else the Vercel MCP `list_teams`. A
  personal scope the CLI can deploy to may be missing from `vercel teams ls`; pass `--scope <slug>` anyway.
- Check the alias is free first: `<project>.vercel.app` may already belong to someone else's site (then add your own
  name with `vercel domains add <name>.vercel.app <project>`).
- Add `.vercelignore`: `.next`, `node_modules`, `.claude`, `.impeccable`, `*.log`, `.env*`. `vercel link` writes a
  `VERCEL_OIDC_TOKEN` into `.env.local`; keep it out of git and uploads.
- `vercel link --yes --scope <slug> --project <name>` then `vercel deploy --prod --yes`.
- Verify the public alias (`<project>.vercel.app`) without auth (`curl -r 0-2000` returns 206 on pages, video and
  images), check `noindex` on pitches, open it in the pane, and give the user the alias, not the hashed URL.
- Later fixes: commit, `vercel deploy --prod --yes`, re-verify the behavior on the live URL.
- Extra names on the same project: `vercel domains add <name>.vercel.app <project>` makes them production domains,
  public and following every prod deploy. `vercel alias set` points at one deployment and sits behind Vercel
  Authentication (302 to vercel.com/sso-api) on teams with standard protection.
- Two sites from one app by host: route in `src/proxy.ts` with `NextResponse.rewrite`, not next.config rewrites. On
  Vercel, config rewrites sent the home page's RSC request (`/?_rsc=`, behind prefetches and logo clicks) to a path
  that does not exist (404 in the console on every page). Pages still come from the edge cache (`X-Vercel-Cache: HIT`).
- After a deploy, warm the edge: request every page, hero file and share image once; the first cold request after a
  deploy took 5s to paint, warm ones 0.2s to first byte.
- Hero video: one master, then AV1 (10-bit), HEVC (10-bit, `-tag:v hvc1`) and H.264 at 1080p and 720p, put in the server
  HTML (`dangerouslySetInnerHTML`, since React drops the `muted` attribute autoplay needs) with `<source media>` for the
  size (720p under 1024px; `prefers-reduced-motion: no-preference` so reduced motion downloads nothing) and codec
  `type`s; a failing source falls through to the next. Content-hashed names served `immutable`; AVIF/WebP posters and
  an inline 48px blur frame paint first; data saver strips the sources once scripts run; a watchdog resumes the loop
  after any pause the page did not ask for (the in-app pane paused it on resize and never restarted it). Scripts:
  `scripts/borrowed/hero_media_sweep.py`, `make_hero_media.py`.
- Share cards: `opengraph-image.tsx` + `twitter-image.tsx` per site with `next/og`, the hero scene captured without
  text (hide whatever object would sit under the headline), the brand and headline in the site font (Google serves
  WOFF to an old user agent; Satori reads WOFF, not WOFF2), `metadataBase` per site so the links are absolute.
- If the user's request needs an MCP that is not authorized (Supabase, Stripe), say it needs `/mcp`; do not ask for
  tokens.
